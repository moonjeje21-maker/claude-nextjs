# Playwright MCP로 오류 수집 · 수정 계획

- 날짜: 2026-10-04
- 프로젝트: claude-nextjs (브랜치 `feat/layout-components`)
- 상태: 완료 (2026-10-04, 커밋 전) — 결과는 맨 아래 "완료 기록" 참고

## Context (왜 하는가)

Playwright MCP(브라우저를 자동으로 조작해 주는 도구)로 지금 앱에서 나는 오류를 모으고, 원인을 찾아 고친 뒤 다시 확인해 달라는 요청이다. 진행 순서는 ① 수집 → ② 원인 분석 → ③ 해결 → ④ 테스트 → ⑤ 안 고쳐졌으면 ①부터 반복.

①·②단계는 파일을 바꾸지 않는 작업이라 계획 단계에서 이미 실행했다. 아래가 그 결과다.

## 1단계 결과: 오류 정보 수집 (완료)

이미 켜져 있던 개발 서버(`http://localhost:3000`)를 Playwright로 열어 확인했다.

| 확인한 곳 | 한 일 | 콘솔 오류 | 네트워크 실패 |
| --- | --- | --- | --- |
| `/` (시작 화면, 데스크톱) | 열기, 테마 → 다크, 토스트 띄우기, 탭 전환, 팝업 열기 | 0건 | 0건 (23개 요청 모두 200) |
| `/dashboard` (데스크톱) | 열기, "공식 문서" 펼치기, 사이드바 접기/펼치기, 사용자 메뉴 열기 | 0건 | 0건 |
| `/this-page-does-not-exist` | 없는 주소 열기 | 1건 (아래 설명) | 404 1건 (의도한 것) |
| `/` (375×812 휴대폰 크기) | 열기, 모바일 메뉴 열기, 가로 넘침 검사 | 0건 | 0건 |
| `/dashboard` (휴대폰 크기) | 모바일 메뉴로 이동, 사이드바 열기 | 0건 | 0건 |

코드 검사 (파일을 바꾸지 않는 방식):

- `npm run lint` — 오류·경고 없음
- `npx tsc --noEmit` (타입 검사) — 오류 없음

## 2단계 결과: 원인 분석 (완료)

**앱 코드에서 고쳐야 할 오류는 발견되지 않았다.** 관찰된 것은 3가지다.

1. **404 콘솔 오류 1건 — 정상 동작, 고칠 것 없음**
   없는 주소를 일부러 열었기 때문에 서버가 404(페이지 없음)로 답했고, 브라우저가 그 사실을 콘솔에 적은 것이다. `src/app/not-found.tsx`의 안내 화면("페이지를 찾을 수 없습니다" + "홈으로 가기")은 제대로 나왔다.

2. **`.playwright-mcp/` 폴더가 git에 잡힘 — 고칠 것**
   Playwright MCP가 화면 기록(`.yml`)과 콘솔 기록(`.log`)을 프로젝트 안 `.playwright-mcp/`에 저장한다(현재 20여 개, 112K). `.gitignore`(git이 무시할 파일 목록)에 없어서 `git status`에 새 파일로 나온다. 실수로 커밋될 수 있다.

3. **접힌 사이드바의 사용자 메뉴를 Next.js 개발 도구 버튼이 가림 — 선택 항목**
   `/dashboard`에서 사이드바를 접으면, 화면 왼쪽 아래의 Next.js 개발 도구 버튼(개발 서버에서만 보이는 동그란 버튼, 기본 위치 `bottom-left`)이 사이드바 맨 아래 사용자 버튼(홍길동) 위에 겹쳐 클릭을 가로챈다. Playwright 클릭이 `<nextjs-portal> intercepts pointer events`로 시간 초과됐다.
   - 배포한 사이트에는 이 버튼이 없으므로 실제 사용자에게는 영향이 없다. 개발 중과 자동 테스트에서만 불편하다.

## 3단계: 해결 (승인 후 진행)

### 3-1. `.gitignore`에 Playwright MCP 출력 폴더 추가

파일: `.gitignore` — 맨 아래에 추가

```gitignore
# playwright mcp (브라우저 자동화 도구가 남기는 화면·콘솔 기록)
.playwright-mcp/
```

이미 만들어진 `.playwright-mcp/` 폴더는 지우지 않는다(무시만 한다).

### 3-2. (선택) Next.js 개발 도구 버튼을 오른쪽 아래로 옮기기

파일: `next.config.ts`

```ts
const nextConfig: NextConfig = {
  // 개발 도구 버튼이 접힌 사이드바의 사용자 메뉴를 가리지 않도록 오른쪽 아래로 옮긴다
  devIndicators: {
    position: "bottom-right",
  },
};
```

- 근거: `node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/devIndicators.md` (이 Next.js 버전에서 `position` 옵션 확인함)
- 단점: 토스트(화면 오른쪽 아래에 잠깐 뜨는 알림)가 떠 있는 몇 초 동안 버튼이 토스트 모서리와 겹칠 수 있다. 사용자 메뉴는 계속 있는 버튼이고 토스트는 잠깐 뜨는 것이라 오른쪽 아래가 덜 불편하다고 판단했다.
- 이 항목이 필요 없으면 빼고 3-1만 진행해도 된다.

### 고치지 않는 것

- 404 콘솔 오류 (정상 동작)
- `.mcp.json` (사용자가 만든 Playwright MCP 설정 파일. 커밋 여부는 사용자가 정한다)

## 4단계: 테스트

1. `git status --short` — `.playwright-mcp/`가 더 이상 안 나오는지 확인
2. `npm run lint` 와 `npm run build` — 둘 다 통과하는지 확인 (`next.config.ts`를 바꾸면 개발 서버가 스스로 다시 시작한다)
3. Playwright로 다시 확인
   - `/dashboard` → 사이드바 접기 → 사용자 버튼 클릭 → 메뉴("계정", "로그아웃")가 열리는지
   - `/` → "토스트 띄우기" → 토스트가 보이는지
   - `/`, `/dashboard` 데스크톱·휴대폰 크기에서 콘솔 오류 0건인지 (`browser_console_messages`)

## 5단계: 반복

4단계에서 오류가 하나라도 남으면 1단계(수집)로 돌아가 같은 순서로 다시 진행한다. 새 오류의 원인과 고친 내용은 이 파일에 이어서 적는다.

## 완료 기록 (2026-10-04)

### 고친 것

- `.gitignore` — `.playwright-mcp/` 추가 (3-1)
- `next.config.ts` — `devIndicators.position: "bottom-right"` 추가 (3-2)

### 테스트 결과 (4단계)

- `git status --short` — `.playwright-mcp/`가 목록에서 사라짐
- `npm run lint` — 오류·경고 없음
- `npm run build` — `Compiled successfully`, `/`, `/_not-found`, `/dashboard` 3개 모두 정적 페이지로 생성됨
- Playwright 재확인
  - `/dashboard`(1280×800) 사이드바 접기 → 사용자 버튼 클릭 → "계정", "로그아웃" 메뉴가 열림 (고치기 전에는 클릭이 막혔음)
  - `/` "토스트 띄우기" → "저장되었습니다" 토스트가 뜸
  - `/`, `/dashboard` 데스크톱·휴대폰(375×812) 크기 모두 콘솔 오류 0건, 경고 0건
- 오류가 남지 않아 5단계(반복)는 한 번으로 끝남

### 알아 둘 점

- 개발 서버에서 토스트가 떠 있는 동안 개발 도구 버튼(N)이 토스트 오른쪽 모서리 32px쯤과 겹친다. 글자는 왼쪽에 있어 가려지지 않는다. 배포한 사이트에는 이 버튼이 없다.
- 없는 주소를 열면 콘솔에 404 오류 1건이 찍히는 것은 정상 동작이다.

### 남은 작업

- 커밋하지 않았다. 바뀐 파일: `.gitignore`, `next.config.ts`, 이 계획 파일. `.mcp.json`은 사용자가 만든 파일이라 건드리지 않았다
- 커밋·푸시는 따로 요청받았을 때만, 올릴 내용을 먼저 보여 주고 확인받은 뒤에 한다
