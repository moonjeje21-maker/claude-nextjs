# `/ship` 스킬에 `.claude/` 설정 파일 형식 확인 추가 계획

## Context (왜 하는가)

`/ship`의 2단계(검사)는 바뀐 파일이 `.md`와 `.claude/` 아래뿐이면 통째로 건너뛴다. 그래서 `.claude/settings.json`이나 hook 스크립트는 어떤 검사도 받지 않고 `main`에 들어간다. 이 두 파일이 깨지면 결과가 크다.

- **hook 스크립트 문법 오류**: 깨진 스크립트는 종료 코드 2로 끝난다(직접 확인함). hook에서 종료 코드 2는 "실행을 막는다"는 뜻이라, Claude의 모든 터미널 명령이 막힌다. 고친 것을 커밋하는 명령도 막히므로 사용자가 터미널에서 직접 고쳐야 한다.
- **`settings.json` 형식 오류**: 설정 파일을 읽지 못하면 `main` 차단 hook 등록이 풀릴 수 있다. 막아 주던 안전망이 조용히 사라진다.

이 저장소는 요즘 `.claude/` 파일을 자주 고치므로, 올리기 전에 형식만 확인하는 한 줄을 스킬에 넣는다.

## 용어 설명

- **`jq empty <파일>`**: JSON 파일을 읽어 보기만 하고 아무것도 출력하지 않는 명령. 형식이 틀리면 오류를 내고 0이 아닌 종료 코드로 끝난다. `jq`는 이미 설치되어 있고 `main` 차단 hook이 쓰고 있다.
- **`bash -n <파일>`**: 스크립트를 실행하지 않고 문법만 확인하는 명령.

## 단계별 검토 (과하지 않은지 따져 본 것)

지난 답변에서 꼽은 빈틈 3개와 떠올릴 수 있는 추가 기능을 하나씩 따졌다.

| 후보 | 결정 | 이유 |
|---|---|---|
| `.claude/`의 `.json`·`.sh` 형식 확인 | **한다** | 깨졌을 때 피해가 크고(위 Context), 스킬에 한 줄이면 되고, 실행은 1초도 안 걸린다 |
| hook이 의도대로 동작하는지 시험 (가짜 명령을 넣어 보는 것) | 안 한다 | hook마다 시험 내용이 달라 스킬에 일반 규칙으로 적을 수 없다. hook을 고치는 작업의 계획에서 그때그때 하면 된다 |
| 스킬·에이전트 `.md` 파일의 맨 위 설정 칸(frontmatter) 확인 | 안 한다 | 확인하려면 도구를 새로 설치해야 한다. 틀려도 그 스킬 하나가 안 불릴 뿐이라 바로 눈에 띈다 |
| `.claude/` 밖의 JSON 파일(`package.json` 등) 확인 | 안 한다 | `npm run build`가 이미 잡는다 |
| 설정 파일만 바뀔 때도 `code-reviewer` 부르기 (빈틈 2) | 안 한다 | lint·build가 돌고, `code-reviewer`의 판단 기준은 코드용이다. 올릴 때마다 시간만 는다 |
| "이미 통과했으면 다시 돌리지 않는다" 문장 고치기 (빈틈 3) | 안 한다 | lint·build 경로는 아직 한 번도 실행해 보지 않았다. 실제로 써 보고 문제가 보이면 그때 고친다 |

## 바꾸는 파일 (1개)

`.claude/skills/ship/SKILL.md`의 2단계. 문장 하나를 고치고 한 줄을 추가한다.

```diff
 ## 2. 검사

-바뀐 파일이 `.md` 파일과 `.claude/` 아래뿐이면 건너뛴다.
+바뀐 파일이 `.md` 파일과 `.claude/` 아래뿐이면 1~2번을 건너뛴다.

 1. `npm run lint`와 `npm run build`를 실행한다. 이 대화에서 마지막 수정 뒤에 둘 다 통과했으면 다시 돌리지 않는다
 2. `src/` 아래가 바뀌었으면 `code-reviewer` 에이전트를 부른다. (이하 그대로)
+3. `.claude/` 아래의 `.json`·`.sh` 파일이 바뀌었으면 형식을 확인한다: `.json`은 `jq empty <파일>`, `.sh`는 `bash -n <파일>`
```

오류가 나왔을 때 멈추는 것은 스킬의 "지킬 것"에 이미 있는 규칙("단계가 실패하면 그 자리에서 멈추고 보고한다")이 처리하므로 따로 적지 않는다. `CLAUDE.md`, hook, 설정 파일은 고치지 않는다.

## 확인 방법

1. **두 명령이 실제로 걸러 내는지** (계획 단계에서 이미 확인했고, 고친 뒤 한 번 더 돌린다)
   - 지금 파일: `jq empty .claude/settings.json` → 종료 코드 0, `bash -n .claude/hooks/block-main-commit.sh` → 0
   - 깨진 입력(파일을 만들지 않고 표준 입력으로 넣음): `jq empty` → 5, `bash -n` → 2
2. **`/ship` 실행**: 이번 변경은 `SKILL.md`와 계획 파일뿐이라 `.json`·`.sh`가 바뀌지 않는다. 그래서 새 3번은 "해당 없음"으로 지나가야 하고, 나머지는 지난번처럼 PR 1개로 병합되어야 한다.

새 3번이 실제로 실행되는 것은 다음에 `.claude/settings.json`이나 hook 스크립트를 고쳐 올릴 때 처음 확인된다.
